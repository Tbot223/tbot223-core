# tbot223-core 4.0.0 쉬운 분석 리포트

## 한 줄 결론

`tbot223-core 4.0.0`은 작은 프로그램이나 자동화 도구를 만들 때 반복해서 필요한 기능들을 한곳에 모아둔 Python용 도구 상자다. 전체 품질은 꽤 좋고 바로 써볼 만하지만, 공식적으로 더 믿고 쓰려면 Windows 파일 처리 문제와 자동 테스트 환경을 먼저 정리하는 것이 좋다.

최종 평가는 `7.9 / 10`이다. 쉽게 말하면 `100점 만점에 79점 정도`다.

## 이 라이브러리는 무엇을 해주나

프로그램을 만들다 보면 자주 필요한 일이 있다.

- 파일 읽기와 쓰기
- JSON 파일 저장과 불러오기
- 로그 남기기
- 오류가 났을 때 원인 정리하기
- 여러 작업을 동시에 실행하기
- 프로그램 전체에서 같이 쓰는 값 관리하기

`tbot223-core`는 이런 기능을 하나의 패키지로 묶어준다. 특히 이 라이브러리는 “일이 성공했는지 실패했는지, 실패했다면 왜 실패했는지”를 항상 비슷한 모양으로 돌려주는 방식을 중요하게 여긴다.

비유하면, 모든 작업 결과를 그냥 말로 대충 알려주는 것이 아니라 아래처럼 정해진 양식의 보고서로 돌려주는 방식이다.

```text
성공했나요? 예/아니오
문제가 있었나요? 문제 설명
어디서 일어났나요? 상황 설명
결과물은 무엇인가요? 실제 데이터
```

이 방식 덕분에 프로그램을 쓰는 사람은 결과를 더 예측하기 쉽다.

## 분석은 어떤 버전을 기준으로 했나

이 문서는 `4.0.0` 버전을 기준으로 한다. 현재 열려 있는 `dev` 브랜치는 개발 중인 상태라서 정상 작동하지 않는 부분이 있었고, 사용자의 요청에 따라 정식 평가 대상에서 제외했다.

기준 정보는 다음과 같다.

| 항목 | 내용 |
|---|---|
| 분석한 버전 | `4.0.0` |
| 분석한 commit | `8a9e1090a3bdc7301a24eb559e9b3df0403fd424` |
| 분석 환경 | Windows, Python 3.14.4 |
| 테스트 결과 | 220개 중 219개 통과, 1개 실패 |
| 테스트 커버리지 | 88% |
| 패키지 빌드 | 성공 |

## 점수는 왜 7.9점인가

좋은 점이 많다.

- 기능이 다양하다.
- 사용법을 설명하는 문서와 예제가 많다.
- 테스트가 꽤 많이 작성되어 있다.
- 외부 라이브러리에 거의 의존하지 않는다.
- 패키지로 빌드했을 때 정상적으로 만들어졌다.

하지만 감점할 부분도 있다.

- Windows에서 파일 잠금 관련 테스트 1개가 실패했다.
- 테스트에 필요한 도구 목록이 별도 파일로 정리되어 있지 않다.
- GitHub에서 코드가 바뀔 때마다 자동으로 테스트하는 흐름이 부족하다.
- 일부 기능은 Python을 잘 모르는 사람에게는 사용 방식이 낯설 수 있다.
- 결과 데이터의 타입을 컴퓨터가 아주 정확하게 추론하기에는 구조가 단순하다.

그래서 “괜찮고 쓸만하다”와 “완전히 안심하고 널리 배포하기엔 조금 더 다듬어야 한다” 사이에 있는 점수로 보았다.

## 가장 좋은 점

### 1. 결과를 일정한 방식으로 돌려준다

많은 Python 코드는 문제가 생기면 바로 오류를 터뜨린다. 그 방식도 좋지만, 여러 작업을 자동으로 처리하는 프로그램에서는 오류 때문에 전체 흐름이 끊기는 일이 불편할 수 있다.

`tbot223-core`는 성공과 실패를 `Result`라는 정해진 모양으로 돌려준다. 예를 들어 파일 읽기가 실패해도 프로그램이 바로 멈추는 대신, 실패 이유를 담은 결과를 받을 수 있다.

이 방식은 자동화 도구, 내부 관리 프로그램, CLI 도구를 만들 때 꽤 편하다.

### 2. 문서와 예제가 많다

한국어와 영어 문서가 모두 있고, 예제도 41개가 있다. 작은 라이브러리치고는 설명 자료가 풍부한 편이다.

기능이 아무리 좋아도 사용법을 모르면 쓰기 어렵다. 이 점에서 `tbot223-core`는 다른 개인/소규모 라이브러리보다 친절한 편이다.

### 3. 테스트가 꽤 잘 되어 있다

전체 테스트 220개 중 219개가 통과했다. 테스트 커버리지는 88%였다.

테스트 커버리지란 “코드 중 얼마나 많은 부분을 실제 검사해봤는가”에 가까운 숫자다. 88%면 작은 라이브러리 기준으로는 좋은 편이다.

### 4. 설치 부담이 작다

이 라이브러리는 실행할 때 필요한 외부 패키지가 없다. 즉, 다른 많은 라이브러리를 줄줄이 설치하지 않아도 된다.

이런 구조는 설치 문제를 줄이고, 오래 유지하기에도 유리하다.

## 가장 걱정되는 점

### 1. Windows 파일 잠금 문제가 있다

테스트 중 1개가 실패했다. 내용은 큰 파일을 읽을 때 파일 잠금을 걸고 푸는 과정에서 Windows에서 `PermissionError`가 난 것이다.

쉽게 말하면, 파일을 안전하게 읽기 위해 “잠깐 내가 쓰는 중이니 건드리지 마”라고 표시했다가, 그 표시를 풀 때 문제가 생긴 상황이다.

모든 기능이 망가졌다는 뜻은 아니다. 하지만 파일을 많이 다루는 라이브러리에서 Windows 파일 잠금 문제는 중요하다. 그래서 가장 먼저 고쳐야 할 문제로 보았다.

### 2. 자동 품질 검사 흐름이 부족하다

현재 패키지를 배포하는 GitHub Actions 흐름은 있지만, 코드가 바뀔 때마다 자동으로 테스트를 돌리는 흐름은 부족하다.

사람이 매번 직접 테스트하면 빠뜨릴 수 있다. 반대로 자동 테스트가 있으면 새 기능을 넣거나 코드를 고칠 때 문제가 빨리 드러난다.

### 3. 개발에 필요한 도구 목록이 정리되어 있지 않다

테스트를 돌리려면 `pytest`, `pytest-cov`, `numpy`, `build` 같은 도구가 필요했다. 그런데 이런 개발용 의존성이 별도 파일로 명확히 정리되어 있지 않았다.

새 사람이 프로젝트를 받아서 테스트하려고 할 때 “무엇을 설치해야 하지?”에서 막힐 수 있다.

### 4. 초보자에게는 `Result` 방식이 낯설 수 있다

Python에서는 보통 문제가 생기면 예외가 발생한다. 그런데 이 라이브러리는 문제를 `Result`라는 값으로 돌려주는 방식을 많이 쓴다.

이 방식은 자동화에는 좋지만, Python 기본 방식에 익숙한 사람에게는 처음에 어색할 수 있다.

## 기능별 쉬운 평가

| 기능 | 쉬운 설명 | 평가 |
|---|---|---|
| `Result` | 성공/실패 결과를 정해진 양식으로 돌려주는 기능 | 매우 좋음 |
| `ExceptionTracker` | 오류가 어디서 왜 났는지 정리해주는 기능 | 좋음 |
| `FileManager` | 파일과 JSON을 읽고 쓰는 기능 | 좋지만 Windows 잠금 문제 있음 |
| `LogSys` | 프로그램 기록을 파일과 화면에 남기는 기능 | 간단한 용도로 좋음 |
| `AppCore` | 여러 작업을 동시에 실행하고 CLI 입력을 처리하는 기능 | 자동화 도구에 유용함 |
| `Utils` | 해싱, 비밀번호 검증, 딕셔너리 검색 같은 잡다한 도우미 기능 | 실용적임 |
| `GlobalVars` | 프로그램 전체에서 같이 쓰는 값을 관리하는 기능 | 편하지만 조심해서 써야 함 |

## 다른 도구와 비교하면 어떤가

`tbot223-core`는 한 가지 기능만 아주 깊게 파는 전문 도구라기보다, 작은 프로그램을 만들 때 필요한 기본 도구들을 모아둔 세트에 가깝다.

예를 들어 파일만 다룰 거라면 Python 기본 기능인 `pathlib`, `os`, `shutil`만으로도 충분할 수 있다. 로그만 중요하다면 `loguru`나 `structlog` 같은 전문 라이브러리가 더 강력하다. 여러 작업을 크게 분산 처리해야 한다면 `ray`나 `dask` 같은 도구가 더 맞다.

하지만 작은 자동화 프로그램에서 파일, 로그, 오류 처리, 작업 실행을 한 번에 정리하고 싶다면 `tbot223-core`가 편하다.

## 어떤 사람에게 잘 맞나

잘 맞는 경우는 다음과 같다.

- 개인 프로젝트를 빠르게 만들고 싶은 사람
- 내부 자동화 도구를 만드는 사람
- 파일 저장, 로그, 오류 처리를 한 패키지로 묶고 싶은 사람
- 실패를 예외가 아니라 결과값으로 받고 싶은 사람
- 외부 의존성이 적은 라이브러리를 선호하는 사람

조심해야 하는 경우는 다음과 같다.

- 아주 큰 서비스의 핵심 기반으로 쓰려는 경우
- 타입 검사가 매우 중요한 팀 프로젝트
- 구조화 로그나 추적 시스템이 필요한 운영 서비스
- 대용량 파일, 원격 저장소, 분산 처리가 핵심인 프로젝트
- Python 표준 예외 방식을 강하게 선호하는 사용자

## 먼저 고치면 좋은 것

가장 먼저 할 일은 세 가지다.

1. Windows 파일 잠금 실패를 고친다.
2. 테스트와 빌드에 필요한 개발 도구 목록을 파일로 정리한다.
3. 코드가 바뀔 때마다 자동 테스트가 돌도록 GitHub Actions를 추가한다.

그다음에는 아래를 개선하면 좋다.

- `Result`가 담는 데이터 타입을 더 정확하게 표현하기
- 오류 처리 중 불필요하게 화면에 출력되는 메시지 줄이기
- 로그 기능에서 내부 순서에 의존하는 부분 정리하기
- 보안상 조심해야 하는 기능을 문서에 더 분명히 쓰기

## 최종 판단

`tbot223-core 4.0.0`은 “작은 Python 프로그램을 만들 때 필요한 기본 도구 모음”으로 보면 꽤 잘 만든 라이브러리다. 문서와 예제가 많고, 테스트도 많이 되어 있으며, 설치 부담도 작다.

다만 아직 “아무 걱정 없이 모든 환경에서 믿고 쓰는 라이브러리”라고 말하기에는 부족하다. 특히 Windows 파일 잠금 문제와 자동 테스트 환경은 빨리 정리하는 편이 좋다.

쉽게 정리하면 다음과 같다.

```text
개인 프로젝트와 내부 도구용: 좋음
작은 자동화 프로그램용: 좋음
대형 서비스의 핵심 기반: 아직 조심
정식 배포 신뢰도: 조금 더 개선 필요
```

그래서 최종 평가는 `7.9 / 10`이다. 지금도 충분히 쓸만하지만, 위의 핵심 문제를 고치면 `8점대 중반`까지 올라갈 수 있는 라이브러리다.
